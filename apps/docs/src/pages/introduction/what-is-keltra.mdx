# What is Keltra \[Typed asset paths for modern frontend frameworks.]

## Overview

keltra is a small tool that makes the asset paths in your code type-safe. It scans your asset folders and generates a typed manifest, so every image, font, and media file in your project gets autocomplete and type-checking — and a renamed or deleted file fails the build instead of 404ing in production.

You know the bug: someone renames `hero.png` to `hero-2x.png`, the build passes, and the image 404s three days later. keltra makes that impossible.

## How it works

keltra runs alongside your dev server and your production builds. It scans the folders you point it at, writes a small typed manifest into `.keltra/`, and watches for changes — so types stay in sync as you add, rename, or delete files. No codegen step to remember, no manual refresh.

Because the manifest is also generated during a production build, missing assets show up in CI, not in production.

## Why keltra

- **Autocomplete everywhere.** Every asset path in your editor is a suggestion, not a guess.
- **Type errors for missing files.** Rename an image and TypeScript tells you exactly where it broke.
- **Framework-native.** Works with Vite, Next.js, and more, from a single package.
- **Zero runtime overhead.** The generated manifest is just types — it disappears at build time.

## Pick your API

keltra exposes the same generated types through whichever API fits your codebase: a typed path helper you can pass anywhere a string is expected, or a drop-in `Image` component with a typed `src`. Both read the same manifest, so you can mix them freely.
